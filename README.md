# 失联之后 · MCP 联机版

当前玩法版本：1.4。支持单人体验，以及人类现场员与 AI 远程操作员合作。首次游玩可在进入页展开玩法说明；AI 的上手说明通过 MCP 自动提供。

需要 Node.js 22.12 或更新版本。建议用 `npm ci` 安装锁定依赖。此仓库只包含游戏源码、测试和通用说明，不包含个人隧道、凭据、运行日志与私人试玩记录。

服务默认仅监听本机。远程席接口没有独立的公网身份认证，请勿直接暴露服务端口；跨设备连接需自行配置带访问控制的安全连接。对局保存在内存，停止后端会丢失当前对局。

本轮新增克制的双侧氛围事件、可信最终回执和舒适度设置。机制边界与交测步骤见 [信息关系恐怖说明](docs/ATMOSPHERE.md)。游戏内“玩法说明”也包含队伍核验指南和独立自检入口。

一款中文非对称信息双人合作生存游戏。**现场员**被困在失联的深空科研站内，**远程操作员**坐在远端控制端。
两人看到的信息完全不同，而且不一定都是真的。

联机模式下，远程操作员是一个通过 **MCP** 接入的 AI，它读取的是服务端单独投影给它的那份数据，
直接对同一局游戏下达远程指令——不再需要任何复制粘贴。

## 架构

```
                    ┌─────────────────────────────────┐
                    │       Game Engine（权威）        │
                    │   WorldState（唯一真值来源）      │
                    └───────────────┬─────────────────┘
                    投影层 src/game/views.ts（权限隔离）
                ┌───────────────────┴────────────────────┐
        FieldView │                                       │ OperatorView
                  ▼                                       ▼
   HTTP + WebSocket /ws                          MCP Server /mcp
                  │                                       │
          浏览器（现场员 UI）                    AI 远程操作员（MCP 客户端）
```

三层状态严格区分：

| 层 | 内容 | 谁能拿到 |
|---|---|---|
| **WorldState** | 真实危险、真实未知目标位置、隐藏物资、哪台传感器在说谎 | 只有服务端 |
| **FieldView** | 所在舱室、相邻通道、可见物品、背包、线索、氧气体感 | 只有浏览器 |
| **OperatorView** | 精确氧气/电力/完整度、分区供电、全部舱门、传感器读数、隐藏警报 | 只有 MCP |

隔离在**数据层**完成：`projectField()` 会抹掉 `power / integrity / alerts / entity / hazard / hiddenItems / lastScan` 并把氧气量化成区间；
`projectOperator()` 只输出系统读数，`server/mcp.ts` 在架构上只允许调用远程席出口，无法触碰 `run.state`。
前端即便打开开发者工具，也拿不到另一侧的信息。

## 运行

```bash
npm install

# 1) 启动联机服务（游戏同步 API + WebSocket + MCP Server）
node start-server.mjs
#   游戏同步 API : http://127.0.0.1:8787/api/runs
#   MCP 端点     : http://127.0.0.1:8787/mcp   （Streamable HTTP）

# 2) 启动游戏前端
npm run dev
```

在开始界面填入服务地址（默认 `http://127.0.0.1:8787`），点击 **创建联机任务**。
界面顶部会出现联机状态栏，显示远程操作员的连接状态、显示名与最近一次操作。

### 让 AI 搭档接入

**A. 支持 Streamable HTTP 的客户端**：直接指向 `http://127.0.0.1:8787/mcp`。

**B. 只支持 stdio 的客户端**（Claude Desktop、Cursor 等）：

```jsonc
{
  "mcpServers": {
    "shilian-zhihou": {
      "command": "node",
      "args": ["/绝对路径/start-server.mjs", "--stdio"],
      "env": {
        "GAME_SERVER": "http://127.0.0.1:8787",
        "MCP_OPERATOR_NAME": "搭档"
      }
    }
  }
}
```

接入后让 AI 调用一次 `game_status()` 即可就座，现场员界面会立刻显示
`远程操作员：搭档 · 已连接`。

## MCP 工具

| 工具 | 说明 |
|---|---|
| `game_status()` | 对局编号、回合、难度、任务目标、暂停与结束状态 |
| `operator_view()` | 仅远程席可见的全部信息 + 一段明确的「信息边界」声明 |
| `operator_log(limit?)` | 最近的远端席操作回执、系统变化与警报 |
| `operator_scan(area)` | 扫描区域（支持「东侧走廊」「7」「逃生舱」；传 `信号` 则执行信号追踪） |
| `operator_door(door_id, action)` | `lock` / `unlock` |
| `operator_power(zone_id, action, target_zone?)` | `on` / `off` / `reroute` |
| `operator_drone(target)` | 派无人机探索、查看危险、捎带轻量物品；支持 `现场员` |
| `operator_trace(target?)` | 追踪未知信号（耗时 2 回合，可指定舱室聚焦分析定位关系） |

先调用 `game_status()` 获取对局标识。所有写操作必须携带本局 `run_id` 与 `round_id`；重新开始后需重新读取，旧轮指令会被拒绝。多局并存时应与现场员核对对局。`operator_name` 用于设置显示名。
每个写操作都会直接修改同一局的 WorldState 并通过 WebSocket 实时推送到浏览器。

**AI 不是全知管理员**：`operator_view()` 里没有现场画面、没有舱内真实情况、没有未知目标的真实位置。
传感器会损坏、延迟、认错东西，`未检测到异常` 不等于安全。信息边界随每次调用一起返回。

## 自动回退

MCP 不可用时，旧的协作方式完整保留：

- **联机服务未启动** → 可在进入页选择单人任务。
- **联机中但远程席无人接入** → 现场员可以点「我来兼任远程席」，服务端按远程席权限单独下发简报。
- **MCP 接管期间** → 服务端对浏览器的远程数据接口返回 `423`，界面提示席位已被接管。
- **MCP 掉线超过 60 秒** → 席位自动释放，界面自动恢复手动模式。
